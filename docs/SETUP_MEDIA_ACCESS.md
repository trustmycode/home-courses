# Настройка доступа к материалам

Медиа-служба не публикуется на `workers.dev` и доступна приложению только через служебную привязку `MEDIA`. Каждый внутренний запрос дополнительно подтверждается секретом `MEDIA_INTERNAL_TOKEN`.

## Служебный секрет

Создайте случайное значение длиной не менее 32 байт:

```bash
openssl rand -hex 32
```

Задайте одно и то же значение для обоих Worker:

```bash
cd apps/home-courses
wrangler secret put MEDIA_INTERNAL_TOKEN

cd ../home-courses-media
wrangler secret put MEDIA_INTERNAL_TOKEN
```

Секрет нельзя добавлять в `wrangler.jsonc`, файлы окружения или журнал сборки. Если он отсутствует, обе стороны возвращают 503 и не переходят в публичный режим.

## Cloudflare Access

Для сайта задайте две переменные окружения:

- `CF_ACCESS_TEAM_DOMAIN` — адрес вида `https://<команда>.cloudflareaccess.com`;
- `CF_ACCESS_AUD` — тег аудитории приложения; несколько тегов разделяются запятыми.

Приложение проверяет RS256-подпись `Cf-Access-Jwt-Assertion`, издателя, аудиторию и срок действия. Внешняя политика Cloudflare Access всё равно должна закрывать домен сайта: проверка в приложении служит вторым рубежом.

## Локальная разработка

В режиме разработки можно явно задать `DEV_USER_ID` и `DEV_USER_EMAIL`. Значений по умолчанию нет. Локальная конфигурация D1 и R2 не содержит `remote: true`, поэтому обычный запуск не меняет боевые данные.

## Проверка

1. Прямой адрес медиа-службы отсутствует.
2. Запрос к `/media/...` без действующего Cloudflare Access завершается отказом.
3. Приложение получает материалы через привязку `MEDIA`.
4. Неверный или отсутствующий `MEDIA_INTERNAL_TOKEN` даёт 401 или 503.
5. `npm test -- --run` в `apps/home-courses-media` проверяет полный ответ, диапазон, `HEAD` и отказы авторизации.
